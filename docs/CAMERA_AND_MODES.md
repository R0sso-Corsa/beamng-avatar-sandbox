# Character choice and Classic-inspired camera

The mod's enabled state and character choice are separate. `avatarSandbox_main.setCharacterMode("roblox")` selects Roblox mode only while the mod is enabled; `"beamng"` selects the typical BeamNG experience. The manually bindable character-mode action switches the choice. Enabling the mod does not automatically select an avatar. Default choice is BeamNG. Disable and mission exit return the choice to BeamNG.

A future engine adapter is installed with `attachCharacterAdapter({enter=function() ... return true end, leave=function() ... return true end})`. It must atomically claim or restore character visuals, camera, controls and native player/vehicle state. False/error results reject ordinary transitions without changing the chosen mode. Mission/unload make a best-effort leave call then clear local lifecycle state; engine restoration on a failed callback needs runtime handling. No adapter is supplied yet: selecting Roblox without one records the choice while `avatarActive` stays false and native gameplay is untouched. A visible settings selector remains pending.

`avatarSandbox/camera.lua` supplies a camera instance through `new()`. Activate it only within the avatar adapter. `look(deltaYaw, deltaPitch)` takes radians, clamps pitch to +/-80 degrees and wraps yaw. `zoom(wheelSteps)` takes positive values to zoom out, with a 0–15 m range, initial distance 3 m and 0.5 m increments. First person enters at 0.30 m or closer and leaves at 0.45 m or farther. These are project settings, not measured Roblox constants.

The behavior follows [Roblox Classic camera](https://create.roblox.com/docs/workspace/camera): orbit the character and zoom into first person. This is independent math, not copied Roblox camera scripts. Target smoothing, automatic recentering, shift-lock and device-specific input are not implemented.

The adapter supplies focus and eye positions in metres, Z-up, as `{x,y,z}`. Heading zero looks +Y; positive yaw rotates toward -X, matching the movement driver's heading convention. `segment` provides the desired focus-to-camera boom for a host sphere sweep. `pose` accepts a safe obstruction fraction in [0,1], shortens the boom with clearance and returns position, forward, first-person/head-visibility flags and movement heading. Occlusion does not alter requested zoom or force first-person mode. The adapter must ignore the local avatar in its camera collision query, perform near-plane/eye collision handling, convert forward to engine orientation, hide the local head/accessories when appropriate and update movement heading. First-person flags alone do not change visibility.

Offline tests cover orbit limits, zoom bounds, first-person entry/exit, obstruction, invalid input, independent mode selection, duplicate transition prevention, disable/mission restoration and failed entry. Actual camera/input calls, vehicle transitions, body visibility and rendering have not been verified in BeamNG.
