# Local diagnostics and on-screen controls

The BeamNG UI app `Avatar Sandbox Controls` is packaged under `ui/modules/apps/avatarSandboxControls`. Add it to your layout through UI Apps after installing the mod. Its structure follows [BeamNG app documentation](https://documentation.beamng.com/modding/ui/app_creation/); app loading has not been verified in the current game build.

The panel loads the GE controls adapter and dependencies. It provides mod enable/disable, Roblox/normal BeamNG choice, optional building tools, interaction, held movement/jump controls and a copyable local debug report. Missing avatar/driver backends disable movement; selecting Roblox without an adapter remains an inactive choice. Building tools cannot activate without a Rust backend. Camera mouse/zoom bindings remain pending. UI status refreshes once a second; closing the panel stops polling and releases held controls. Mouse-up, leaving the panel and window focus loss also release them. Touch/gamepad access and screen layout require further work.

`telemetry.lua` keeps at most 100 events with monotonically increasing sequence numbers, bounded component/message strings and a cumulative error count since clear. Records cover control failures, character transition callback errors, interaction exceptions and driver failures. `snapshot` returns copies, and `clear` drops history/error counts without reusing sequence numbers. Additional engine/Rust adapters should call `record` when they reject work. It does not automatically catch arbitrary engine exceptions, process crashes or Rust failures without adapter reporting. History is in-memory only and is lost when its extension/game process is reloaded. No networking or automatic upload is implemented.

The debug report combines mod, driver, building and telemetry status. Click Prepare debug report, then select/copy the text when reporting an issue. Record the BeamNG version and reproduction steps manually. Callback error text can include paths or other details supplied by an adapter; review the report before sharing it. No player positions or identifiers are deliberately collected.

The UI sends only whitelisted commands to its GE controller; arbitrary Lua strings are not accepted as commands. Existing normal BeamNG bindings are unchanged. Native controls/camera takeover remains the character adapter's responsibility, not this UI app.

Offline checks cover event limits, report isolation, control rejection, transition-error capture, JavaScript command whitelist, focus release and teardown. Driver and character/camera regression checks still pass. Run the Python checks with `lupa`, and `node tests/controls_ui_smoke.js` from the repository root. In-game app appearance, bindings and report delivery remain unverified.
